 P2 - THE SHADOW BOX
   PREDICTION      written on ______
     Bounds: left -h, right +h, bottom -h, top +h, near 0.1, far 100 (DirectionalLight.cpp builds
     glm::ortho(-h, h, -h, h, near, far)).  With the course's h = 20 the volume is 40 x 40 x 99.9 = 159,840 cubic units;
     our level 1 uses h = 24 so 48 x 48 x 99.9 = 230,169.6.
     WHERE IS OUTSIDE: light space x = -world x for our sun, so |x| > h is outside (press Z twice: h = 6, the box then
     covers only x in -6..6).  GAME EFFECT: outside the box the lookup hits the border value 1.0 = nothing in the way = lit.
     So standing in a shaded place beyond the box edge you burn.  Screenshot: HUD says OUTSIDE SHADOW BOX and shows SUN.
     WHY A DIRECTIONAL LIGHT NEEDS A BOX WITH NO POSITION: a shadow map is a finite texture; the rays are parallel, so
     "where the camera looks from" is arbitrary but the AREA those rays are captured over must be chosen. Resolution
     is spread over that area (texels per world unit = res / (2h)); a box too large wastes it, too small leaves holes.
     Ortho (not perspective) because the rays are parallel - same reason the HUD uses ortho.
